# MechWright — 完整产品与工程方案

> 状态：正式建设规范（目标是完整版，而非削减功能的 MVP）  
> 产品：MechWright / 机械铸造师  
> 定位：面向 RimWorld 机械体创作的离线优先、全流程、可视化、原生 XML 工程工作台  
> 目标游戏：RimWorld 1.7，覆盖 Core、Royalty、Ideology、Biotech、Anomaly、Odyssey；未来版本以独立兼容档案扩展。  
> 原则：用户决定设计数据，软件负责理解约束、正确构建、充分预览、安全导出。本文是目标蓝图，**不表示这些功能已实现**。

## 1. 产品目标与边界

MechWright 不是套表单的 XML 编辑器，也不是只会生成单个 `ThingDef` 的向导。其最终目标是在一个工程内完成标准机械体的身体结构、种族属性、武器与弹丸、近战、PawnKind、生命阶段、显示贴图、原生能力与相关定义、机械培育、机械集群/敌袭接入、声音、残骸、拆解、翻译、引用关系、校验、打包和标准 XML 输出；允许从纯空白工程开始，也允许读入原版与 Mod 定义作为模板。

**完整覆盖**的工程解释：所有经识别的原版 XML 字段都能被无损读取和编辑；高频字段拥有领域专用可视化；低频字段有类型化通用属性编辑器；未知/新版本字段有高级 XML 无损编辑入口。不存在“为了外观统一而丢掉原生字段”的情况。覆盖度由实际字段清单、导入导出回归测试证明，不能只凭描述宣称 100%。

非目标：游戏引擎替代品、C# 机制自动生成器、绕过 DLC 授权、复制再分发官方素材、未经允许改写用户的游戏目录。允许引用既有 Def 或带着外部 Def 引用导出，但必须检测依赖。特殊玩法能力可配置其**原版支持**的字段；需要自定义 C# 的行为仅提示“外部实现”，不能凭空生成看似有效的 XML。

## 2. 首要用户流程

1. **工程入口**：新建/打开/导入已有 Mod/从原版机械体模板派生；选择游戏版本、已安装 DLC、目标导出模式。
2. **机械体身份**：命名、DefName（建议 `MP_` 前缀作为项目可配置规则）、标签、文字、所属文件夹与命名空间。
3. **身体搭建**：选择复用原版 BodyDef 或建立完整的 CorePart—子部件树；可视化层级、覆盖份额、Inside/Outside、Top/Middle/Bottom；编辑部件血量、标签和分组。
4. **基础属性**：分类编辑 `ThingDef` 与 `race`、`statBases` 等；向导显示建议值、原版继承值和用户覆写值三种不同状态。
5. **攻击系统**：近战 tools 关联身体组；装备枪械、verb、弹丸、爆炸、伤害与穿甲；依赖引用、连射时序和理论 DPS 即时计算。
6. **显示与声音**：四向贴图（含 west 镜像）、图层叠加、绘制大小、偏移、阴影、遮罩、生命阶段、SoundDef 引用；不把贴图尺寸误认为 bodySize。
7. **生态集成**：PawnKind、CP、控制带宽、培育 Recipe、机械集群和机械族袭击权重、拆解物、死亡残骸、翻译等；每项显式启用。
8. **审阅与导出**：检查依赖与字段、跨文件引用、原版类型/版本约束、差异及警告；预览完整输出树、生成原生 XML、复导入比对，确认后原子保存。
9. **持续编辑**：自动保存草稿、撤销/重做、快照与分支外备份、字段级搜索、预设和复用，不丢失未识别字段。

完整设计交互支持**自由编辑和引导式编辑两种并行模式**；引导模式可以根据“是否独立身体/是否远程武器/是否培育”等选择隐藏无关项，随时返回修改；高级模式可访问全部字段和 XML。向导、画布、检查器始终编辑**同一份文档模型**，杜绝双向状态不一致。

## 3. 全 DLC 原生定义覆盖策略

| 来源 | 覆盖对象 | 原则 |
|---|---|---|
| Core | 通用 ThingDef、PawnKindDef、BodyDef/BodyPartDef、BodyPartGroupDef、近战、装备、弹丸、生命阶段、声音、伤害、资源、翻译 | 基础来源 |
| Royalty | 机械族/机械集群相关 Def、Royalty 扩展字段和引用 | 按实际资源与可用 DLC 发现 |
| Ideology | 适用的标签、思想关联和扩展字段 | 没有关联时不强行添加 |
| Biotech | 机械师控制、带宽、充电、机械培育、相关 Recipe、工作模式及种类字段 | 机械体主要专项 |
| Anomaly | 可被机械体定义引用的原生 Def 与新增字段 | 条件启用 |
| Odyssey | 1.7 新增的机械体、跨环境/世界相关原生 Def 字段 | 条件启用 |
| 第三方 Mod | 名称空间、继承、Def 引用、属性扩展、PatchOperation | 可导入，来源标记；未知字段无损保留 |

**不得手工臆造覆盖清单。** 建立可版本化的“Def Catalog”：从用户本地合法游戏安装中读取 XML，结合类型元数据和有审查记录的字段描述包生成目录。需处理 `ParentName`、`Abstract`、`Name`、`Inherit`、`MayRequire`、`PatchOperation`、`defName`、`li`、`Class`、文本与 XML 属性。DLC 目录应有来源标记、启用状态和生效优先级，用户可看见字段来自哪一层，不能将“文件存在”当作“游戏运行时一定激活”。

重要限制：**单靠 XML 样本无法发现所有合法的 C# 定义字段**。字段目录必须组合静态结构、官方/可靠的类型元信息与可扩展声明；自动提取只负责候选，不代表合法性。每个字段记录：Def 类型、路径、数据类型、是否多值、允许枚举/引用目标、默认/继承规则、版本和 DLC、来源证据、UI 编辑器、验证规则、序列化策略、可视化特性。未确认合法性的字段不应作为普通控件静默写出。

### 3.1 标准机械体必须可配置的覆盖面

- `ThingDef`：基础继承类；`label`/`description`；`statBases`（含移动、质量、三类护甲、价值、控制带宽、环境/燃烧/心灵属性等）；`race`（body、body size、health scale、intelligence、thinkTree、mechWeightClass、lifeStages、声音、残骸、机体工作等）；`comps` 原生配置；`tools`；`butcherProducts`；引用。
- `PawnKindDef`：race、combatPower、weaponTags、weaponMoney、生成组上限、集群资格、战斗分组、生命阶段 graphicData、portraitZoom、原生 abilities 等。
- `BodyDef`：corePart、parts 树、相对 coverage、depth、height、groups、customLabel、children 依附关系。可复用原版或创建。
- `BodyPartDef`：hitPoints、solid、skinCovered、bleedRate、alive、tags（视觉/听觉/意识/移动/操作/过滤等）、附带的原版参数。
- `BodyPartGroupDef`：组定义和 tools/服装/其他引用关系。
- 普通近战 `Tool`：capacities、power、cooldownTime、linkedBodyPartsGroup、armorPenetration、chanceFactor 及原生可用扩展。
- 装备枪械 `ThingDef` + `verbs`：远程精度、冷却、预热、射程、连发、发射声、弹丸、装备生成标签、交易/掉落。
- 弹丸 `ThingDef`：damageDef、damageAmountBase、armorPenetrationBase、speed、stoppingPower、原生爆炸/火焰/次级伤害配置。
- 关联：`RecipeDef`（培养周期、材料、研究、产物）、`FactionDef` 中 mech raid 的 `PatchOperation`、声音/特效/贴图路径、翻译与包级 `About.xml`。
- 原生能力：`AbilityDef`、`HediffDef`、`DamageDef`、`EffecterDef`、`StatDef` 等可作为**关联 Def** 按目录能力编辑，不要求每台标准机械体都强制生成这些文件。
- 任何不直接属于机械体的 Def 类型仍通过**通用 XML 树 / 引用浏览器**访问，但不虚构领域专用 UI。

### 3.2 字段与来源状态

每个字段在 UI 中必须区分：`Inherited`（继承，未写入）、`Explicit`（用户明确覆写）、`DefaultSuggestion`（仅推荐，未确认）、`Unavailable`（版本/DLC 不支持）、`UnknownRaw`（可保留，未获语义确认）。默认值只是编辑器建议，不得在新建或导出时被自动当成已确认的真实值。显示“重置为继承值”“显式写出”两种独立操作。

## 4. XML 精确性与导入导出契约

- XML 是**最终权威交付物**，工程 UI 状态只是生产模型；游戏必须能读取生成结果。项目内部使用版本化项目清单保存窗口布局、编辑历史与资产映射，但不要混进游戏 Def XML。
- 支持“新建标准 Def / 从原版派生 / 导入现有 XML 修改 / 批量 XML 文件夹导入 / 项目另存 / 输出 Mod 目录结构”。
- 对新建文件使用稳定布局：`About/About.xml`、`1.7/Defs/...`、`1.7/Textures/...`、`1.7/Languages/...`、可选 `Patches/...`、项目编辑器元数据目录 `.mechwright/`（不打包进 Mod）。
- 受支持字段的结构化输出要确定性：固定序列化顺序、规范数值格式、原始大小写准确、合法 XML escaping、缩进一致；禁止复制未知字段作为标准字段。
- 导入已有 XML 必须保留未知节点、属性、注释、`li` 顺序、`Class` 属性、`Inherit`、`MayRequire`、`ParentName`、`Name`、`Abstract`、PatchOperation、局部原始格式（能保留的尽量保留）。**只改一处字段不应重写所有文件。**
- 将“规范化新文件导出”与“编辑已有文件后最小差异写回”区分实现；后者是语法保持 AST + 目标节点补丁，不允许只用 DTO 全量序列化覆盖未知内容。
- 实时 XML 预览应同时提供：生成结果、与原稿 Diff、字段来源、Def/路径引用点；允许“高级 XML”编辑，编辑后解析与冲突合并。
- 导出前严检：重复 defName、dangling refs、非法枚举或类型、身体树环/无核心、无效覆盖率、贴图缺失、武器标签与 PawnKind 不匹配、未声明依赖、缺少引擎支持的 Class、Patch XPath 无匹配等。无法凭静态验证证明的，标明“需游戏运行验证”。
- 写文件前预览变更和覆盖冲突、显式确认目标；临时文件 + 原子替换（同卷）+ 备份 + 回滚，默认不直接改 RimWorld 安装目录。
- 拒绝 DTD、外部实体及不受信任外部资源，设定输入大小与深度上限；导入文件不会触发任意代码执行。

## 5. 身体结构编辑器（关键差异化能力）

中心使用“**树状部件 + 装配层示意图 + 命中权重视图**”三种同步表现，绝不将 XML 层级简单画成外观上互相遮盖的硬壳。

- 树视图：corePart、parent/child、复制/移动、左右镜像生成、重复部件快捷操作、每一层 coverage 及子部件组。
- 层级装配：2D schematic，而非伪装为游戏中真实 3D hitbox；节点依附线、Inside/Outside 高亮、Top/Middle/Bottom 分层，切换定位和编辑焦点。
- 命中模拟：显示相对于父节点的 coverage 和相对于整机的基础层级乘积；明确**基础权重不等于最终受击概率**，实际命中受 RimWorld 伤害规则影响。允许表达覆盖率总和异常警示，不擅自重整用户数值。
- 核心保护：显示 ArtificialBrain/Reactors 等来源、被父部件摧毁的连带风险；Inside 不等于绝对防护。
- 原版能力视图：SightSource / HearingSource / ConsciousnessSource / MovingLimbCore / ManipulationLimbCore 等，识别缺少必要能力的配置；不添加“部件坏了自动禁用枪械”之类的游戏不存在的行为。
- 支持从种族对应 BodyDef 实际解析展示，不将“纹理中的视觉位置”当作碰撞或身体部件高度。
- 交互：节点搜索、展开/折叠、拖拽放置预验证、键盘移动、批量对称编辑、操作撤销、字段相关帮助、错误定位。

## 6. 武器与战斗可视化

- 标准近战：部件组与伤害类型引用检查，显示每个 Tool 的独立攻击参数。
- 远程枪械：可视化时间轴（预热—连发—冷却）、弹道/散布示意、射程圆、基础精度曲线、理论伤害与 DPS 计算；公式与假设可查看，**不把理论 DPS 当作实际战斗结果**。
- 弹丸与爆炸：爆炸半径、命中格、伤害、穿甲、火焰特性、受击目标覆盖预览；区分距离/范围/穿甲单位，不在编辑器中模拟完整游戏伤害系统。
- 对引用的 vanilla 武器提供“引用不拷贝”“派生覆写”“独立新建”明确选择。
- 导入武器与 PawnKind 时自动检查 weaponTags、weaponMoney、生成是否可实际装备；对没有攻击手段的单位给出阻断或警告（视用途）。

## 7. 贴图与资产工作台

- 接受 PNG 透明图与 RimWorld 多方向命名（north/south/east/west 及实际 graphicClass 规则）；方向缺图是否可镜像或继承必须由图形类约束判定，不能不加检查地镜像。
- 支持预览网格、旋转方向、贴图 drawSize、阴影、offset、遮罩、同种类不同生命阶段；多实例参考以及与部件结构并列预览。
- 采用懒加载与缓存，不让大型原版贴图目录挤爆内存；贴图预览使用游戏外近似渲染，**不能宣称与 Unity 游戏效果像素级一致**。
- 素材库按来源/Def/用途检索；禁止自动复制 DLC 专有素材到输出包。默认对已安装资源仅建立只读引用与本机预览。

## 8. 复古数码视觉与交互规范

用户提供的白色芯片图标是**唯一产品徽标来源**：`assets/branding/icon-original.png` 为原图；派生透明/黑底方形图标保持造型，不重新设计符号，不引入复杂光效。程序启动图标、窗口、托盘/任务栏和安装包围绕同一徽标制作适配尺寸；小尺寸必须清楚可辨。

### 色彩与排版
- 主背景：#0B1014；次级表面：#151E24；浮层：#1E2A32；主文字：#E6ECEB；次文字：#A3B1B4。
- 重点色：克制的冷青 #8DBCB4；辅助暖金 #CFB482；危险色 #D87C76。高对比状态通过形状和文本区分，不只依赖颜色。
- 复古感来自终端网格、工业仪表、短标签、精密标尺、微弱状态灯、等宽数值；禁止大面积噪点、模糊玻璃、刺眼发光、装饰性频闪和与交互无关的扫描线。
- 中文正文用清晰系统字体；数据/DefName 用可读的等宽字体；支持 100%–200% 缩放；不用嵌入字体来制造版权与分发问题。
- 动画目标 120–220ms，有 easing、可中断、同一操作仅一个状态来源；支持减少动态效果。过度动画不得拖慢实际交互。

### 主要界面
```
┌ 顶部：项目名称 / 来源版本 / DLC / 搜索 / 保存 / 导出 / 错误数 ┐
│ 左侧：工程导航与 Def 树 │ 中央：当前可视化工作台 │ 右侧：属性检查器 │
│ 可收起资产与模板库       │ Body / Combat / Graphic 等 │ 字段来源/建议值/继承  │
├ 底部：问题列表 / XML 差异 / 依赖关系 / 任务和日志（可调整）       ┤
└ 状态栏：未保存、当前文件、验证状态、缓存状态                    ┘
```
- 工作台有项目概览、身体、属性、战斗、渲染、生态、依赖、导出等**任务视图**，不是到处散落互不一致的弹窗。
- 面板自适应、最小宽度约束、可拖动与记忆，至少兼顾 1366×768；任何文本、X、按钮都不得被遮挡，溢出必须滚动、换行或折叠。
- 选择/悬停/聚焦/错误/禁用四态以上可区分；单击、双击、拖拽语义统一；焦点与真实选中值同步，不能只画选中框。
- 空状态引导下一步；危险操作二次确认、明确撤销；错误提示包含“何处、为什么、如何修复、跳转目标”，不弹无意义的大段文字。
- 键盘优先：Ctrl+N/O/S/Z/Y、Ctrl+F、Delete、Enter、Esc、方向键与 Tab 原生焦点规则；可在偏好中开启 WASD 画布导航，但不抢夺文本输入。
- 读屏名称、键盘可达性、对比度、减少动态效果与高 DPI 为正式验收项。

## 9. 技术方案与选择依据

**主路线：C# / .NET 10 LTS / Avalonia 12.x / Skia 渲染 / MVVM。** .NET 10 LTS 在 2026-11 仍受支持；Avalonia 12 提供跨平台桌面 UI、编译期 XAML 和默认编译绑定。Windows 11 是重点发布平台，但核心保持可移植。12.x 具体 patch 在实际搭建时锁定并通过构建验证，不能只追最新而引入未经验证的依赖。

- UI：Avalonia XAML、CompiledBindings、CommunityToolkit.Mvvm；大树与数据列表使用**已确认许可与可维护性**的虚拟化控件或自研轻量虚拟面板，避免凭名字依赖付费控件。
- 领域与校验：C# 类型安全不可变模型、命令式编辑与可逆操作、数据源追踪；跨界面单状态源。
- XML：`System.Xml.Linq` / `XmlReader` + 保留原始语法片段的 round-trip 扩展，不能只靠 JSON 中间模型重建所有 XML；Diff/patch 独立服务。
- 缓存与索引：内存只读快照 + 可取消后台构建 + 增量失效；按需加载图片和 Def 详情。普通工程可无外部数据库；当扫描规模需要持久索引时再引入 SQLite，并保证迁移与损坏恢复。
- 日志：结构化日志，仅本地默认记录；异常提示与敏感路径脱敏；无默认遥测/账号/在线依赖。
- 分发：Windows 单文件/自包含包依平台测试决定；CI 构建、签名可选；应用离线启动；后续可扩展 macOS/Linux 而不绑死系统 API。

目录代表最终目标；当前仓库不会为了摆架势而创建大量空项目。只在真正产生代码与清晰职责时建对应模块。**源代码仅依赖同层或更内层接口**，Core 不依赖 Avalonia、文件系统或游戏安装；App 不直接解析 XML；Infrastructure 不包含 UI 业务判断。以接口与依赖注入在应用入口组合。避免全局单例状态、“万能工具类”、反射式巨型字段开关、重复 DTO 和逐个字段的手工 UI if/else。

### 数据契约
- `ProjectProfile`：目标版本、启用 DLC/Mod、命名约束、导出目标、文件布局选项。
- `DefIdentity`：Def 类型 + defName + 来源/作用域（引用稳定）。
- `DefGraph`：节点、父子关系、字段值、边/引用、版本化变更序列。
- `FieldDescriptor`：字段路径、类型、可编辑域、版本/DLC、继承/默认与序列化规则、验证器。
- `RawXmlExtension`：不能类型化的节点、注释、属性与原始位置；导入输出必须安全保存。
- `DocumentSession`：唯一编辑状态、dirty 标记、undo/redo 栈、增量校验结果及预览快照。
- `Diagnostic`：Severity、Def、文件、字段路径、message、ruleID、修复建议和定位。
- `ExportPlan`：输出文件、改动集合、潜在覆盖、依赖、诊断及确认状态。

## 10. 性能、稳定性与安全

性能目标必须可测，不允许“感觉很快”：
- 在明确记录硬件、数据集与构建条件后，常规属性编辑输入回显目标 P95 < 50ms；交互动画保持 60fps，慢任务不得占主线程。
- 数千 Def 树节点仍支持流畅展开/滚动；采用虚拟化和索引，不为不可见节点生成控件。10k Def 搜索 P95 目标 < 200ms（索引就绪时）。
- 常用工程热启动目标 < 2s、首次目录索引在后台可取消；工程打开与导出大文件另设基准数据，先量测再立门槛。没有量测报告时不得宣称达标。
- XML 解析、索引与缩略图都可取消；对用户连续输入采用去抖和版本号丢弃陈旧计算；跨线程状态写回只能经过 UI 调度；拖动面板不触发全量重绘。
- 内存为引用缓存设预算与 LRU 淘汰；路径索引不持有纹理完整像素；GPU 资源释放在正确线程；批量导入不卡 UI。
- 输入防护：XML 外部实体与 DTD 禁止、ZIP 解压路径穿越防护、导入大小/深度限制、文本合法字符验证、路径规范化、导出不越过用户指定根、无隐式执行 C#。
- 数据保护：自动草稿、原子写入、覆盖前 Diff、崩溃恢复、可读错误日志；UI 保存成功必须以磁盘结果为准，不先假报成功。

## 11. 质量门禁与验收矩阵

质量与功能同等优先。不得用“快速原型”名义省略契约验证与交互测试。

**自动化测试**
1. Core：字段模型/覆盖率乘积/依附关系/操作撤销与重做/默认继承语义/诊断 ID 稳定。
2. RimWorld：Core 与每个 DLC 的代表性定义导入、ParentName/Abstract/Inherit/MayRequire 解析、引用目录构建、复合 Def 与 PatchOperation、大小写。
3. 无损回归：导入→不修改→导出→语义及关键文本等价；只改一字段→其他字段/属性/未知内容不丢失；再次导入无丢失。
4. 导出：文件结构、DefName 冲突、XPath 目标存在性警告、武器标签引用、Recipe 产品、贴图缺失与非法路径。
5. UI：键盘焦点、真实选中、深树编辑、撤销、脏状态、批量操作、窗口缩放、遮挡、滚动、DPI、多语言和高对比。
6. 稳定与性能：大 Def 库、重复导入、取消重试、异常恢复、内存/帧耗时基准。
7. 实机：使用合法已安装 RimWorld 1.7 + DLC 加载导出包；无法在 CI 访问游戏内容时，通过用户本机手动验收记录，不伪称验证成功。

**功能完成定义**
- 每个字段编辑入口有来源、类型验证、写出行为和测试。
- 跨文件引用能从错误导航到源字段，并能查出全路径。
- 没有丢字段、莫名 XML 补丁、UI 闪烁、输入焦点丢失、被遮挡的文字/控件。
- 导出文件与预览一致，输出不依赖 MechWright 运行。
- 中文及英文均完整，未知字段有兜底编辑方法。
- 性能数据有记录，未达标有明确问题清单而非隐藏。

## 12. 全量交付的实施顺序（不等于缩减版）

产品目标自始锁定**完整功能集**；实际开发必须先处理依赖关系，以免 UI 先行造成频繁重写。按纵向完整功能切片推进，每阶段可运行、可测、可验收，但不能删减最后功能。

**A. 工程与基础技术**：创建 .NET 10 / Avalonia 12 solution；基础主题与窗口、日志、DI、设置、资产规范、CI、测试运行；建立目录与领域边界。交付可启动应用与可靠构建。

**B. 原版定义目录**：Core + 五个 DLC 的 Def 加载、来源/版本、ParentName 与 PatchOperation 解析、字段元数据、引用索引、未知 XML 保留、合法性/许可边界。交付可搜索、可审阅的目录和 fixture 测试。

**C. 完整编辑文档**：DefGraph、字段编辑、唯一会话、自动草稿、撤销、继承与覆写、导入导出 round-trip、原子保存。交付任何 Def 可安全编辑的通用基础。

**D. 专用机械体工作台**：BodyDef、BodyPart、能力、stats、race、PawnKind、weapon/tool/projectile、graphics、sounds、recipe、生成/集群、翻译与包结构的专用可视化。交付标准机械体的端到端流程。

**E. 高级可视化与智能防呆**：身体层级/覆盖率、伤害/射程/连发时间轴、依赖地图、模板库、字段默认值建议、错误一键定位与修复、并列对比、批量修改。

**F. 完整交互与质量闭环**：键盘导航、多窗口/DPI、动效与无障碍、性能基准、安全检查、兼容矩阵和导出实机验收；优化所有高频路径。

**G. 分发与长期维护**：Windows 正式构建与安装、更新文档、许可与第三方声明、贡献者工作流、版本化游戏目录、数据迁移及未来 DLC 的维护制度。

每阶段实现与数据均进 `main`；不擅自创建 feature 分支/PR。**若无法编译/运行/实机测，必须明确报告，不用空白样例冒充功能。**

## 13. 关键产品决策和风险

- **“全覆盖”与维护成本**：字段注册表 + 类型驱动 UI + unknown raw 模式才能跟进新 DLC；逐字段硬编码注定失控。维护可靠的合法来源与回归语料比堆大量界面重要。
- **“原版 XML”与无损编辑**：XML 的继承、PatchOperation、顺序、属性、注释和未知节点不可通过丢弃式转换获得；两种导出模式必须严格区分。
- **“复古数码”与易用性**：仪表视觉只装饰重点，不抢真实数据层级；可读性、输入体验和无闪烁优先。
- **“高性能”与架构规模**：优先减少无效创建、布局、IO 和重解析；不要先上不必要的数据库、微服务、插件容器。
- **原版资源版权**：用户可选择本机安装路径读取/预览，不把 DLC XML、贴图、字体和音效直接提交仓库或分发。
- **兼容 C# 自定义机制**：软件只承诺可表达的原生 XML；未知 C# CompProperties 允许保存引用，但需要在目标 Mod 中真实实现，否则给出提示。
- **第三方库许可**：在加入时审核，并在发布前形成必要的第三方许可证清单；保留仓库现有 Apache-2.0 许可证。

后续编码应先读取 `AGENTS.md` 与本文件，检查 `main` 现状，然后：创建能启动的 Avalonia App + solution + 测试工程；实现项目打开/关闭、唯一定义会话、Core/DLC 定义目录读取器、最小可验证 XML round-trip；将 UI 框架、设计 token 和指定图标接入。每一步按完整蓝图逐步向内扩充，**不以假按钮、静态截图或纯 Mock 表格宣布功能完成**。
