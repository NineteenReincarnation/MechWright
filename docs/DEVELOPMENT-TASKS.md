## 1. 目标与执行原则

MechWright 的交付目标是 **RimWorld 1.7 Core + Royalty / Ideology / Biotech / Anomaly / Odyssey 的机械体原生 XML 可视化工作台**：不会 XML 的用户也能从空白工程创建、编辑、预览、校验、导出一台标准机械体；也能无损导入已有 Mod 继续编辑。完成定义以 **真实游戏可加载、跨文件引用正确、重新导入不丢失数据** 为准，而不以页面数量或 XML 能解析为准。

- **主界面必须保持从上到下的单列参数列表**：左侧语义标签、右侧直接输入；列表、嵌套字段和属性也应通过普通控件完成。预设仅为可选参考，不得强制选机体、武器或身体模板。
- **自由度优先，但不制造无效数据**：支持重复列表项、任意原生 Def、已识别的多态类及复杂嵌套；不能确认的字段只作为候选或高级 XML 内容，不声称其游戏内合法。
- **以用户本机游戏数据为依据**：Core、五个 DLC 的 XML + 程序集字段元数据 + 继承/补丁来源；扫描到不等于合法、能写入不等于能在游戏中加载。绝不打包官方游戏资源。
- **一份文档状态**：列表、身体、战斗、贴图、XML 预览和诊断均编辑同一文档。操作尽可能可撤销；编辑已有文件以最小差异写回，保护未知节点、`li` 顺序、注释、CDATA、`Class`、`ParentName`、`Inherit`、`MayRequire` 与 PatchOperation。
- **命名**：本项目新增示例 DefName 统一使用 `MP_` 前缀；应用面向其他 Mod 时仍应允许用户自定义命名规则，避免产品逻辑硬编码。
- **开发范围**：本文件记录尚未闭环的任务，不重复建设已完成的功能，不以增加冗余文档或大量无意义测试替代交付。每次先检查当前实现、测试和字段覆盖记录，再从未完成项接续。

## 2. 已有基础与已确认缺口

| 领域 | 已有基础（保留并复用） | 尚未闭环 |
| --- | --- | --- |

| XML 操作 | `DefDocument`、撤销/重做、未知节点与属性保留、部分 CDATA/列表回归 | 复杂节点全链路无损往返、继承/补丁的语义验证 |
| 字段目录 | `DefCatalog`、`NativeFieldCatalog`、`GameAssemblyFieldCatalog`、`InspectorFieldCatalog` | Core + 全 DLC 可审计的真实字段证据矩阵；字段类型、版本和来源对应关系 |
| 参数列表 | `DocumentWorksheetView`、`VisualWorksheetView` 与基础类型输入 | 重复 `li` 成员的零 XML 操作、嵌套多态结构的类型化编辑、统一字段状态 |

| 战斗 | `NativeListEditor`、自由模块编辑、`WeaponAnalysis` 理论 DPS | 专用枪械/弹丸/爆炸/组件工作台与完整战斗预览 |
| 原版资料 | 原版机械体库、武器候选和贴图参考 | 区分原始 XML/继承值/经补丁后的可推导生效值 |
| 生成/培育 | PawnKind 常用字段、原生培育 Recipe、资源/贴图导入 | Faction/Patch/机械集群接入、动态材料研究目录 |
| 验证 | 文件内字段与身体基础规则、跨文件重复 DefName、部分引用浏览 | 跨文件引用诊断、依赖和 DLC 校验、Patch XPath、实际游戏加载验证 |

**证据边界**：截至上述基线，`docs/FIELD-COVERAGE.md` 仍明确标记全 DLC 实际覆盖率未知，已有大量测试基于合成 XML。不得将编辑器内部安全回归计入游戏字段覆盖率。

## 3. P0 — 优先完成底层闭环

### MW-01 · 全 DLC 字段证据矩阵

- 基于用户本机合法 RimWorld 1.7 安装，按 Core / Royalty / Ideology / Biotech / Anomaly / Odyssey 逐包扫描原生 Def XML 与程序集元数据。
- 记录每个字段：Def 类型、路径、字段类型、集合/多态、枚举或引用目标、来源包、继承/默认语义、序列化策略、UI 入口及证据等级。
- 解决“XML 样本出现”“DLL 公开字段候选”“已验证 XML 往返”“真实游戏加载通过”四类证据混用问题；未确认字段不得静默按安全标量插入。
- 将可重复生成的**统计报告与缺口清单**更新到 `FIELD-COVERAGE.md`，不提交游戏原版 XML、DLL 或专有资源。
- **验收**：能够查看按包、Def 类型和字段路径分组的已验证/候选/未知清单；每项可追溯来源；不虚构 100% 覆盖率。

### MW-02 · 复杂列表与多态结构的直列式完整编辑

- 复用 `NativeListEditor` / `FreeformModuleEditor` / `DocumentWorksheetEditor`：将选中 `li`、新增、删除、复制、上下移动与嵌套字段修改接入实际主工作站。
- 提供逐项可展开的列表成员和专用类型控件；可明确定位重复子项、`Class` 多态节点，支持字段/属性增删；无需手写 `<li>` 或 XML 路径。
- 区分“新增空白项”“复制已选项”“引用原版项”；不默认套用样例、不误选重复父节点、不改变未编辑内容。
- 所有操作统一走可撤销的文档命令；失败时 XML、revision、dirty 状态不变。保留注释、CDATA、未知属性与顺序。
- **验收**：普通用户不打开源码即可完成 `tools`、`verbs`、`comps`、`abilities` 等代表性列表的添加→逐项填写→排序→保存→复导入；复杂结构有清晰错误提示。

### MW-03 · 跨文件引用、继承与 PatchOperation 检查

- 扩展 `MechWorkspace.Validate` 与 `DefinitionReferences`，不仅浏览引用，还能在全工程及已加载目录中检查缺失、冲突、来源和 DLC 依赖，导航到具体文件/字段。
- 正确区分显式值、`ParentName` 继承、`Inherit` 列表语义、`MayRequire` 条件和 `PatchOperation` 的潜在影响。无法准确模拟的运行时行为必须标为“需游戏验证”，不得当作通过。
- 提供 Faction / PawnKind / Body / Recipe / weapon / projectile / Ability / Hediff 等真实引用链诊断；对无法匹配的 Patch XPath 给出明确来源和警告。
- 导出前统一展示阻断错误、可忽略警告、未知依赖；禁止“只要 XML 合法就显示完成”的误判。
- **验收**：人为制造缺失引用、重复 DefName、错误 DLC 依赖和无效 Patch XPath 时，诊断定位正确；合法的第三方引用不会被直接误判为游戏加载错误。

### MW-04 · 实际游戏验收与可复核覆盖记录

- 建立从空白创建机械体→导出 Mod→在对应 1.7 + DLC 环境加载→检查日志→生成 Pawn→查看贴图、部件、攻击、培育等→重新导入核对的标准流程。
- 自动化测试继续覆盖最小必要的 XML 往返、继承、列表、多态节点、撤销与导出；补充经过合法原版安装抽取的**本地测试流程**，不向仓库发布受版权保护的 fixture。
- 记录游戏版本、启用 DLC、执行者、结果、未验证事项及可复现错误；CI 通过只能表述为编译/测试通过，不等于游戏加载成功。
- **验收**：至少完成一条端到端的真实标准机械体交付证据链，并能按 DLC 持续扩充验证表。

## 4. P1 — 机械体专用设计能力

### MW-05 · 身体编辑器可视化

- 在已有身体部件编辑器上补充**部件树 + 2D 装配关系示意 + 命中基础权重**三种同步视图，不把 XML 的层级错误描绘为贴图或真实 3D 碰撞。
- 支持选中定位、父子依附、Inside/Outside、Top/Middle/Bottom、部件复制/重排、左右对称辅助、Coverage 和完整 BodyPartDef 关联。
- 明确相对 Coverage 与累计基础权重的区别；不把累计值标成游戏最终受击概率；提示异常结构与关键功能部件。
- **验收**：从空白建造多层身体并可视化，修改任一视图后其余视图和 XML 一致，导出重载后层级不变。

### MW-06 · 独立战斗与武器工作台

- 基于原生 Def 实现近战 Tool、远程武器 `verbs`、`ThingDef` 弹丸、爆炸/伤害与常用 `CompProperties` 的语义化字段编辑。
- 提供原版引用、不复制原版的引用、派生修改、独立创建四种清晰操作语义；按真实 schema 判断多态 `Class` 和组件参数合法性。
- 可视化预热—连发—冷却时间轴、射程、命中与基础爆炸范围、理论 DPS；公式和未知继承值必须说明，不伪称准确模拟游戏战斗。
- **验收**：可从零创建一套原生可用的武器与弹丸并关联机械体，不需要手写 XML；引用、字段和导出结果均可检查。

### MW-07 · AI、PawnKind、机械集群和派系生成接入

- 补充 ThinkTreeDef、原生 Job/工作模式/行为相关**可验证字段及引用**的可视化；不承诺自动生成自定义 C# AI 算法。
- 补充 PawnKind 生成资格、CP、标准机械族/集群关联、FactionDef/PatchOperation 编辑与生成权重；仅在对应游戏机制原生支持时提供专用控件。
- 结合当前 DLC 和外部 Mod 依赖展示来源、可用性和冲突；自定义行为缺少 C# 实现时给出清晰提醒。
- **验收**：可以配置一台机械体从单位定义到原生生成入口的引用关系，并对不可确认的生成行为明确标注实机验证要求。

### MW-08 · 关联 Def 与动态原版资料

- 完善 BodyPartDef / BodyPartGroupDef / AbilityDef / HediffDef / DamageDef / EffecterDef / SoundDef / RecipeDef 等关联 Def 的类型化常用字段，不仅提供“创建空白定义+手填原生字段名”。
- 从本机目录动态查询材料、科技、配方父模板、可引用 Def 等；原有固定建议保留为**可选快捷项**，不锁死第三方 Mod 扩展。
- 升级原版机械体库：区分原始 XML 显式字段、普通继承解析值、可验证的补丁结果与无法推导的 C# 运行时效果；来源和不确定性始终可见。
- **验收**：支持真实动态检索与选择；在未知字段/外部 Def 场景下能继续安全编辑和输出。

### MW-09 · 贴图、声音与资源预览完善

- 在现有 PNG / ZIP 导入和三方向预览上完善 N/S/E/W 规则、GraphicClass 类型判断、缺省方向镜像的合法性、绘制大小、offset、阴影与生命阶段贴图引用。
- 贴图预览清晰区分本地近似效果和游戏内最终渲染；资源导出自动组织路径，引用保持一致，不擅自复制 Core/DLC 图片。
- 对大型资源启用按需加载、缓存释放和可取消扫描；检查缺图和不存在的引用。
- **验收**：导入方向贴图后无需手写路径；重新打开工程后引用、方向及输出资源保持一致。

## 5. P2 — 工作站体验与工程交付

### MW-10 · 统一操作路径与交互

- 以“新建/导入 → 选择机械体 → 纵向列表修改 → 专用视图辅助 → 检查 → 导出”为唯一主工作流。
- 逐步合并重复入口，不叠加新的大型向导、无意义按钮或孤立弹窗；原始 XML 与高级属性留在高级工具，不阻挡普通工作流。
- 统一字段状态：继承、显式写出、建议未确认、不可用、未知；支持搜索、焦点/真实选中同步、错误定位、键盘导航、撤销重做、高 DPI。
- **验收**：不会 XML 的用户不依赖额外指导即可完成标准机械体；无需反复切窗口或手填路径。

### MW-11 · 全工程导出与数据安全

- 导出 `About/About.xml`、`1.7/Defs/`、Textures、Languages、必要 Patches 与依赖声明；项目内部元数据不混入 Mod 输出。
- 区分新文件的规范化输出与导入文件的最小差异修改；输出前展示冲突/变更，原子保存、备份和可恢复错误。
- 检查外部资源路径、重复/缺失 Def、Patch 及跨文件依赖；不修改 RimWorld 安装目录。
- **验收**：一次操作输出可直接安装的完整 Mod 目录；失败不破坏原始工程，重新导入保持内容一致。

### MW-12 · 测试、性能、架构与发布

- 对字段目录扫描、10k Def 检索、大型 XML、连续撤销重做、纹理加载建立可复现性能基准；先测量瓶颈，再优化热点，不为架构美观引入数据库或复杂抽象。
- 继续使用现有 Windows CI、单元测试和 UI Smoke Test；针对关键路径增加必要的 Windows UI 交互与异常恢复测试。
- 逐步梳理 Core（领域契约/命令/诊断）、RimWorld（原生 schema/XML）、Infrastructure（IO/缓存）、App（交互与展示）的职责；维护唯一数据源，不大规模推倒重写。
- 检查中文/英文界面、窗口缩放与遮挡、文件夹结构、第三方许可和真实发布文件。
- **验收**：性能报告可复现、主要工作流 CI 通过、Windows 实际交互稳定、文档和分发行为一致。

## 6. 执行顺序与完成标准

建议按照依赖逐批推进，而非平均分配进度：

1. **先做 MW-01 + MW-02**：拿到可信字段语义，并让复杂列表在 UI 中可完整操作。若尚无合法游戏安装，以可安全交付的字段目录工具和结构编辑功能为先，不虚构真实扫描结果。
2. **随后 MW-03 + MW-04**：完成验证链和一次真正游戏加载验收，再扩大功能范围。
3. **再推进 MW-05 ~ MW-09**：每个专用编辑器都必须复用 P0 的 schema、文档命令和验证机制。
4. **持续实施 MW-10 ~ MW-12**：配合功能切片改善易用性、可靠性、性能和发布质量，不将其做成拖到最后的一次性重构。

### 单项任务完成判据

- [ ] 已检查相关现有代码，尽量复用已有结构，没有重复造轮子。
- [ ] 新增 UI 实际可用，使用者无需手写普通字段 XML。
- [ ] 所有修改通过同一文档链，撤销、重做和保存状态一致。
- [ ] 来源不可靠的字段明确标注，不把合法 XML 误称为合法游戏行为。
- [ ] 有对应的必要回归测试；实机未验证时显式记录限制。
- [ ] 更新 `FIELD-COVERAGE.md` 中**真实变化**的证据和待办，不编造数量/百分比。
- [ ] 构建、测试、UI 交互检查结果和提交 SHA 可追踪。
- [ ] 直接提交 `main`，不擅自开分支/PR，不修改不相关功能。

### 与现有自动开发任务的关系

已有的每日“MechWright 单位 XML 全覆盖”开发任务继续负责 MW-01、MW-02 及相关字段证据、往返安全工作的持续推进。**不另起一套重复任务，也不要求每次从头规划**；每次先读取本文件、`FIELD-COVERAGE.md` 与最新代码，然后基于未完成项继续。

> 最终完成标准：无需了解 XML 的使用者，可以在 MechWright 中自由创建一台 RimWorld 1.7 原生机械体，完整配置身体、属性、武器、图形及必要生成/培育关系；导出标准 Mod，经对应 DLC 环境真实加载，通过检查，并能无损重新导入继续修改。
