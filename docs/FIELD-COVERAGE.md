# RimWorld 1.7 单位 XML 字段覆盖追踪

> 基线：2026-11-13；此表记录可审计的证据级别，不是完成率声明。

## 证据等级

- **已确认可写入 XML**：有对应游戏版本的原版 XML 实例，且编辑后通过往返测试；实际游戏加载仍须单独验证。
- **仅在样本出现**：从本机 Core / DLC Def XML 观察到；样本不代表所有合法字段，也不代表任意 Def 可插入。
- **仅在 DLL 中观察到**：Assembly-CSharp.dll 的公开字段或枚举候选；尚未确认 XML 装载规则。
- **未验证**：无足够样本、元数据或测试，不向用户宣称已支持。

## 当前实现与缺口

| 范围 | 现有实现依据 | 状态与下一步 |
| --- | --- | --- |
| ThingDef / PawnKindDef 基础标量 | InspectorFieldCatalog、NativeFieldCatalog、GameAssemblyFieldCatalog | 部分可编辑；逐字段补充原版 XML + 游戏加载证据 |
| RaceProperties / graphicData | 内置字段目录、DLL 元数据一层嵌套 | 部分可编辑；复杂子类和覆盖规则未验证 |
| statBases | 已观察到的原版 XML 字段与内置常用字段 | 部分可编辑；StatDef 引用合法性未全面验证 |
| comps / verbs / tools / lifeStages | 原生列表编辑器及原始 XML 保留路径 | 列表成员不得当作独立标量插入；需 Class、li、顺序往返测试 |
| BodyDef / BodyPartDef | BodyStructureEditor 及其测试 | 部分支持；实际 DLC 全量字段和树约束待核对 |
| Hediff / Ability / Recipe / 武器 / 弹丸 | 通用 Def 与专项编辑器 | 未完成全字段验证；需分类型构建样本矩阵 |
| Royalty / Ideology / Biotech / Anomaly / Odyssey | DefCatalog 按安装目录分别扫描 | 扫描能力不等于覆盖；每个 DLC 的实测字段数量待记录 |
| 继承 / Class / MayRequire / PatchOperation | DefDocument 原始 XML 模型 | 无损往返与变更最小化仍需系统性回归 |
| 未知 Mod 扩展 | XML 原始节点可保留 | 不应自动作为已验证可插入字段 |

## 本轮改进

- NativeFieldCatalog 对 `li`、`comps`、`verbs`、`tools` 等集合/多态路径禁止直接标量插入；仍保留样本字段供参考。
- 新增针对集合路径、正常 race 标量及拒绝插入后 XML 不变性的回归测试。
- 未获取本机 RimWorld 1.7 全 DLC 的真实 XML 和 DLL，不能生成可信的全量字段数量或覆盖百分比。

## 下一轮优先级

1. 从合法安装的 Core + DLC 扫描结果导出字段清单，分别统计观察到的路径、DLL 候选、内置字段和缺口。
2. 对每种集合建立有来源证据的元素类型/属性/排序规则，不用单纯路径猜测替代 schema。
3. 增加 ParentName、Class、Inherit、MayRequire、注释与未知节点的多文件往返及撤销测试。
4. 在 UI 中显式展示四种证据状态，并为不可信字段阻止静默写入。

## 2026-11-14 增量：多态父节点保护

- NativeFieldCatalog 现在检查样本字段的祖先是否含 `Class` 属性：位于多态对象内部的叶子字段仍作为样本展示，但不提供直接标量插入。避免把 `race Class="..."` 下观察到的字段误当作可安全新建的普通 `race` 子项。
- Apply 再次执行路径安全检查，防止调用方构造 `CanInsert=true` 的集合路径绕过扫描阶段的限制。
- 新增两项回归测试：多态父节点与普通 statBases 字段对照；伪造集合路径被拒绝且 XML 和 dirty 状态保持不变。
- 证据等级：这些是**编辑器安全约束及合成 XML 测试**，不是 RimWorld 1.7 原版 / DLC 实测字段，也不是游戏加载验证。覆盖百分比仍未知。
- 待办：实际安装的 Core + 全 DLC 样本统计、程序集候选和游戏加载验证；另需核对所有合法多态节点的 XML 装载规则，避免把安全阻止误写成字段本身不合法。

## 2026-11-15 增量：目标文档结构校验

- 原生样本目录中的安全标量路径，不能自动证明当前目标文档同一路径可直接修改。Apply 现额外检查**目标 XML** 的每一级父节点是否带 `Class`，以及目标路径是否存在重复同名元素；不明确的情况拒绝写入，交由带类型的专用编辑器处理。
- 新增两项合成 XML 回归测试：目标父节点有 `Class`；目标标量路径重复。两种情况均要求拒绝后原 XML 与 dirty 状态不变。
- 此项属于目标文档防误写保护，**不是** RimWorld 1.7 DLC 字段合法性验证；真实游戏数据覆盖率仍未知。
- 下一步优先实现对重复列表成员的明确定位编辑（保留顺序、属性和撤销），而非放宽标量路径限制。

## 2026-11-16 增量：精确定位列表标量

- NativeListEditor 新增 SetItemField：先用完整 XML 路径定位现有 li，再用相对路径定位唯一现有叶节点。只修改已存在的文本叶子，不猜测重复子项，也不自动创建未知结构；通过 DefDocument.Transform 进入撤销/重做历史。
- 同名列表容器重复出现时拒绝隐式选取首个容器，避免错误修改。
- 新增合成 XML 测试：修改 verbs/li/defaultProjectile 后导出重载、保留 Class/Inherit/注释、撤销与重做；缺失叶子、非法路径、重复容器均拒绝。
- 证据等级：**编辑器结构操作的合成测试**，并非已确认可写入 RimWorld 1.7 的具体字段；该 API 目前是底层能力，尚未宣称已接入全部可视化控件。
- 后续优先级：将精确叶子编辑接入现有列表 UI；为重复子节点提供显式索引定位和专用控件；从合法游戏安装获取 Core/全 DLC 的 XML 与 DLL，建立按包/Def 类型/字段路径的可审计覆盖矩阵。

## 2026-11-17 增量：嵌套重复子节点的显式索引

- NativeListEditor.SetItemField 支持相对路径中用从 1 开始的索引指定重复子元素，例如 `parts/li[2]/coverage`；未写索引时仍必须唯一匹配，避免静默修改第一个 `li`。
- 拒绝不存在的索引、零索引、非法路径和歧义节点，操作失败不应产生脏状态；继续只编辑已存在的文本叶节点，不自动生成未验证字段。
- 新增合成 XML 回归用例：选择第二个重复子节点、导出重载、保留 ParentName / Class / 未知属性及节点、撤销重做；真实 RimWorld 1.7 游戏加载验证尚未完成。
- **现阶段仅完成底层精确定位能力**，未声称已接入直列式 UI；下一步应在实际使用的 DocumentWorksheetView 中提供嵌套列表节点的直观选择和输入控件。
- 本轮没有 Core/全 DLC 的完整 XML 与程序集扫描结果；字段覆盖率仍未知，证据等级属于编辑器合成测试而非游戏字段合法性确认。

## 2026-11-18 增量：现有嵌套字段的直列式 UI

- DocumentWorksheetView 的复杂结构区域新增现有 XML 节点的逐行可视化编辑，使用 DocumentNodes / DocumentNodeRow 的已有类型控件（文本、数值、布尔、枚举）和逐项保存按钮；通过 SaveDocumentNode → DocumentWorksheetEditor.UpdateValue → FreeformDefinitionEditor.SetValue 复用原有可撤销编辑链路。
- 列表内部已存在的叶节点可直接按可见标签填写，不要求用户输入 XML 路径或原始 li 片段。分组只显示结构提示，不作为普通标量写入；未修改的行不触发保存。
- 本次没有新增字段合法性判定或自动创建列表元素的能力。尚需验证 Avalonia UI 运行行为、重复列表项路径、含 Class 的子节点以及真实 Core/全 DLC 数据；不将 UI 接线视为游戏 XML 字段已确认支持。
- 下一步：在现有列表 UI 中提供明确的 li 成员选择、添加/删除/排序与字段证据标识；增加 UI 自动化及真实游戏样本往返测试。

## 2026-11-19 增量：快速添加路径的目标父节点保护

- DocumentWorksheetEditor.AppendFieldPath 在已有父路径出现多个同名分组时拒绝隐式选取第一个；若目标路径经过带 `Class` 属性的父节点，也拒绝无类型信息的快速插入。此限制针对“快速添加标量”入口，**不禁止**高级编辑器对合法多态或重复列表进行明确定位操作。
- 保留唯一普通分组的快速添加能力；使用 DefDocument.Transform 的事务回滚与撤销/重做机制。
- 新增合成 XML 回归用例：多态 race、重复 race、嵌套多态 stats 均应拒绝且不改变原 XML、revision 和 dirty 状态；唯一普通 race 分组仍可添加字段并撤销重做，保留 ParentName、未知节点和注释。
- 证据等级：仅验证编辑器结构安全性；**没有**新增任何已确认的 RimWorld 1.7 Core/DLC XML 字段。真实游戏扫描、全量字段覆盖率和游戏加载验证仍待完成。
- 下一步：优先在直列式 UI 中为重复 `li` 成员提供明确选择、添加、删除和重排操作，并将字段证据状态直接呈现在行内。

## 2026-11-20 增量：列表叶节点 CDATA 保留与无操作保护

- NativeListEditor.SetItemField 在编辑单一 CDATA 文本叶节点时直接修改已有 XText/XCData 节点，避免 XElement.Value 替换节点而把 CDATA 转成普通转义文本。
- 若新值与现有文本相同，直接返回，不产生 Transform、revision 或 dirty 状态变化。
- 若叶节点包含多个文本/CDATA 节点，拒绝普通单值编辑并提示使用高级 XML 编辑器，避免意外合并混合文本结构。
- 新增合成 XML 回归测试，覆盖 CDATA 往返、撤销重做、未知属性保留、无操作不变脏以及混合文本拒绝修改。
- 证据等级：编辑器 XML 无损性合成测试；**未新增原版或 DLC 字段合法性证据**。实际游戏字段扫描与游戏加载验证仍未完成。
- 下一步仍应优先推进直列式 UI 的列表成员选择、新增/删除/重排与 Core + 全 DLC 字段覆盖矩阵，避免将此类 XML 安全改进误计入字段覆盖率。

## 2026-11-21 增量：逐行保存与批量保存使用相同的字段校验

- DocumentWorksheetViewModel.SaveDocumentNode 现在先调用 StandardFieldRules.Validate，再执行 DocumentWorksheetEditor.UpdateValue；之前 CommitDocumentInputs 有此校验，逐行“保存”入口却没有，导致两条编辑路径行为不一致。
- 对于值未变化的行仍不执行写入；不合法输入抛出明确错误并沿用现有 DocumentMessage/ReportError 反馈，不进入 XML 修改链路。已有批量保存校验逻辑不变。
- 证据等级：**应用层校验一致性代码改进**。本轮没有获得原版/DLC XML 或 DLL，也没有新增已确认可写入 XML 的字段。该改动需要 CI 编译与 Windows UI 交互回归；不能视为全字段覆盖进度。
- 后续仍优先完成 li 列表项的零 XML 新增、删除、排序控件及游戏安装扫描生成的按 DLC 字段证据矩阵。建议为逐行保存与批量提交增加相同非法输入的 UI/ViewModel 回归测试，验证失败时 XML、revision、dirty 状态均不变。

- **下一步**：根据真实 Core + DLC 字段证据，完善列表项的类型化新建和属性选择、嵌套 `li` 的直观定位、主页面的字段证据状态和实际游戏加载验证；覆盖率仍为未知。

## 2026-11-22 第二批：列表字段聚焦与本机证据报告（MW-02 / MW-01）

- 结构编辑区域根据当前选择的 `li`，只展示该成员及其子字段；取消成员选择则恢复完整定义的节点列表。源数据仍是原 `DocumentNodes`，不建立第二份可写 XML 状态。
- 新增 `FieldCoverageReport`，直接基于连接到的**本机合法 RimWorld 安装**生成 Markdown 清单：Core/各 DLC 的扫描存在性与有 defName 定义数、观察到的字段路径及类型、来源包和出现次数、编辑器可直插策略、CLR 元数据候选及其是否见于 XML 样本。
- 左侧“连接本机游戏字段”旁增加“导出字段证据清单…”按钮；只在真实游戏目录成功扫描后启用，通过用户选定的目标位置安全写入 Markdown，不向仓库复制任何游戏 XML、程序集或图片。
- 加入合成 XML 的基础 UI Smoke 断言，检查报告同时包含正常标量、受保护的列表子字段以及缺失 DLC 说明；真实运行结果仍以 CI 为准。
- **证据边界**：报告输出的是样本观察结果和候选元数据，仍然**没有**实际 RimWorld 1.7 + 全 DLC 环境的字段覆盖百分比或游戏加载认证；外部 Mod 的新增字段也不属于当前官方样本清单。


## 2026-11-22 第三批：Class / 标量 li 与跨文件诊断（MW-02 / MW-03）

- `NativeListEditor.SetItemClass` 通过选中成员的完整 XML 路径精确设置或移除 `Class` 属性；无变化不产生撤销历史，拒绝控制字符及超长输入，保留同层其他成员、未知属性、`Inherit` 和注释。普通文档配置页已提供对应的 **Class 编辑栏**，不要求手写 XML。
- `DocumentWorksheetViewModel` 针对选中 `tools/li`、`verbs/li`、`comps/li` 提供常用子字段提示。**这些仅是 UI 填写建议**：能选择字段不等于该字段与选定 CLR Class / 游戏版本相容，不把建议计入已验证字段数量。
- 调整空的 `li` 节点显示：当它没有子元素时可作为普通文本叶子编辑（例如 `abilities/li` 中的 DefName 引用）；带子元素的 `li` 仍以分组展示。新增、保存、撤销继续复用已有文档命令链。
- `MechWorkspace.Validate` 新增**保守的跨文件引用检查**：项目内存在相同 DefName 但目标 Def 类型不符时输出 `MW022` 警告；仅在用户已连接本机游戏目录并传入游戏目录时，针对工程和游戏目录都未解析到的已知引用输出 `MW021` 警告。外部 Mod 可以提供缺失的定义，因此两种情况都不视为已确证的游戏加载错误；不连接游戏目录时不把普通原版引用当作缺失。
- 根节点为 `Patch` 的 XML 现在检查标准 `xpath` 字段是否为空或语法无法解析，给出 `MW024` **非阻断警告**；不运行补丁、不假设游戏载入顺序，也不把 XPath 在当前文件里未命中视为错误。
- 补充 `NativeListEditorTests`、`MechWorkspaceTests`、`PatchValidationTests` 和 UI Smoke 场景，针对 Class 无损往返、原文不变、跨文件改名/撤销、未安装原版时的未知引用、XPath 语法、空 `li` 文本编辑进行回归。**最终编译/测试状态以当次 GitHub Actions 结果为准**。
- 后续仍需完整的多态对象字段类型来源与类型合法性检查、实际 RimWorld 1.7 原版 DLC 数据扫描、通过真实 Mod 加载的 Patch XPath 生效检查和更全面的引用路径覆盖。**本增量没有新增游戏实测覆盖率。**


## 2026-11-22 第四批：可定位诊断和 ParentName 继承检查（MW-03）

- 重构诊断行的数据绑定：`DiagnosticRow` 直接保留诊断的 `Code`、`Severity`、XML `Location` 与所属工程 `FilePath`，不再把文件路径拼入不可解析的提示文本。
- 现有“设计检查”页增加可选中的文件与引用诊断列表；普通 XML 配置页增设只在有诊断时出现的折叠列表。点击“定位”能切换到对应文件、Def 和已有的最近 XML 节点，并展开原有高级结构编辑，不新增独立向导。对缺失或 Patch XPath 等不能定位为普通 Def 字段的情况，明确保留源文件路径和无法精确定位的信息。
- `DefValidation` 的 Def 诊断位置改用 `DefDocument.GetPath`，使混排多个 Def 类型时不再误用全局定义索引形成错误的同类型序号。UI Smoke 覆盖多文件、混排类型和实际诊断定位操作。
- `DefCatalog.CatalogScan` 现在从用户本机安装 XML 的 `Name` 属性建立只读 `ParentTemplates` 索引；`TemplateInheritanceDiagnostics` 检查当前工程同类型模板重名（`MW031`）、本地可证明的 `ParentName` 循环（`MW032`），以及在本机扫描结果和工程中都未找到、又没有直接 `MayRequire` 条件的模板名（`MW030`）。均为**非阻断警告**，不模拟模组加载顺序或声称第三方模板不存在。
- 新增 `TemplateInheritanceDiagnosticsTests` 及必要 UI Smoke 验证。此轮修改的是可审计的静态检查和 UI 操作，没有获得原版/DLC 的真实加载结果，不改变全量字段覆盖率未知的结论。
- **后续**：继续验证继承/条件依赖/加载顺序，完整支持对所有引用源类型的检查；在真实游戏中核对 XML、Patch 和父模板解析行为。


## 2026-11-22 第五批：引用链扩展与 DLC 条件语义（MW-03）

- `DefinitionReferences` 仅扩展**显式、可确定类型的原生引用位置**：`ThingDef` 的 `race/body`、`projectile/damageDef`、`verbs/li/defaultProjectile`、`tools/li/linkedBodyPartsGroup` / `capacities/li`、制作配方/研究/配方使用者、`thingCategories/li` 和 `costList`；`RecipeDef` 的产品、研究、工作台、材料过滤器；`FactionDef` 的兵种/组类型；`DamageDef` 的 Hediff / 音效；`ResearchProjectDef` 的前置研究等。仅把列表的 `li` 文本或键名式资源列表识别为引用，不将 `weaponTags`、`tradeTags`、`Class` 等普通标记误判为 DefName。所列路径是实现中的保守白名单，**不代表全 DLC 的所有引用字段已经完成扫描验证**。
